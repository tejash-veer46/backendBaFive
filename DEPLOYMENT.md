# Deploying baFive for free

| Piece    | Host                                   | Free tier notes                                                    |
| -------- | -------------------------------------- | ------------------------------------------------------------------ |
| Database | [Turso](https://turso.tech) (libSQL)   | 5 GB, no card. Keeps data across API restarts.                      |
| API      | [Render](https://render.com) web service | Sleeps after 15 min idle; first request then takes ~30–60 s.     |
| Website  | Render static site                     | Global CDN, always on.                                              |

Both services are described in [`render.yaml`](render.yaml), so Render creates them in one go.

> Why Turso? Render's free web services have no persistent disk — a local SQLite file would be wiped
> on every deploy and every time the service wakes up. Turso is SQLite-compatible, so the same code
> runs against a local file in development and Turso in production.

## 1. Create the database (Turso)

1. Sign up at <https://app.turso.tech> (GitHub login works).
2. Create a database, e.g. `bafive` (pick the region closest to your Render region — Singapore or
   Oregon/Virginia are good defaults).
3. Copy its **URL** (`libsql://bafive-<you>.turso.io`) and create a **token** (Database → *Create Token*,
   read & write, no expiry).

The API creates its tables automatically on first start.

## 2. Deploy API + website (Render)

1. Sign up at <https://dashboard.render.com> with GitHub and give Render access to **both**
   `backendBaFive` and `baFiveApplication`.
2. **New → Blueprint**, pick `backendBaFive` (branch `master`). Render reads `render.yaml`.
3. When asked for values:
   - `DATABASE_URL` → the Turso URL
   - `DATABASE_AUTH_TOKEN` → the Turso token
   - `VITE_API_URL` → leave empty for now
4. Click **Apply**. Two services appear: `bafive-api` and `bafive`.
5. Open `bafive-api`, copy its URL (e.g. `https://bafive-api.onrender.com`), then open `bafive` →
   **Environment** → set `VITE_API_URL` to that URL → **Save, rebuild and deploy**.

Your site is live at the `bafive` service URL. Check the API at `<api-url>/health`.

## Updating

Pushing to `master` (API) or `main` (website) redeploys automatically.

## Settings worth knowing

- `DEMO_MODE=true` seeds demo profiles that like and reply to new users — set it to `false`
  in the `bafive-api` environment before inviting real users.
- `JWT_SECRET` is generated by Render. Changing it signs everyone out.
- `CORS_ORIGIN` is `*` (safe because auth uses bearer tokens, not cookies). To restrict it, set it to
  the website URL.
- Custom domain: add it on the `bafive` service (Settings → Custom Domains); both Render and Turso
  free tiers allow this.
